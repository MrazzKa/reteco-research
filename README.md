## Run (WSL, from `reteco-research/scripts`)

```bash
source ../../.venv/bin/activate
D=../../reteco_data_v11; K=../../RETECO/starter_kit; R=../research/runs_v12
# BM25, depth 1000, train + dev
python bm25s_run.py --data $D --kit $K --splits train dev --track 1 --domains iota quant \
    --k 1000 --conditions 1a 1b_query+step --out $R/bm25/t1
# dense index (GPU, resumable) and exact retrieval
python dense_index.py --data $D --track 1 --domains iota quant --model bge-small --max-len 512 --out $R/emb

    --max-len 512 --emb $R/emb --out $R/dense/bge-small_L512/t1

python hybrid.py --track 1 --conditions 1a 1b_query+step --domains iota quant \
    --bm25 $R/bm25/t1/runs --dense $R/dense/bge-small_L512/t1/runs --data $D --kit $K --out $R/hybrid/demo.json
python make_results.py --root .. --out ../research/RESULTS.md
```

## How to make a submission (2026-11-02)

Everything that defines a submitted run is frozen in `configs/submission.json` (models and revisions,
quantisation, prompts, fusion weights, depths, ReasonEmbed weight, MaxP on/off, tie key, seeds); `scripts/submit.py`
reads only that file, the release topic files and the corpora (never qrels). One run file per (variant, domain),
because Track-2 topic ids repeat across domains. Main runs: `1a`, `1b`, `2a_history`; fallbacks: `1a_noRE`, `1b_noRE`,
`2a_nomaxp`, `2a_maxp` (also listed in the config under `_main_runs` / `_fallback_runs`). The official format is `qid Q0 docid rank score run_id`, depth 1000.

```bash
cd ~/semeval-reteco/reteco-research/scripts && source ../../.venv/bin/activate
D=../../reteco_data_v11            # for test: the folder with the test release (same layout, split name "test")
K=../../RETECO/starter_kit
# 1. runs (LLM generations are cached by sha1(prompt + model + text); missing ones are generated with vLLM in
#    ../../.venv-llm, which needs CC=~/semeval-reteco/tools/bin/cc; ReasonEmbed document vectors are cached per domain)
python submit.py --config ../configs/submission.json --variants 1a 1b 2a_history 2a_nomaxp 2a_maxp 1a_noRE 1b_noRE \
    --data $D --split test --out ../research/runs_v13/submit/test
# 2. dev check of the same pipeline (official checker + scorer, compares with the research numbers)
python submit.py --variants 1a 1b 2a_history --data $D --split dev --out ../research/runs_v13/submit/dev
python score_submission.py --sub ../research/runs_v13/submit/dev --variants 1a 1b 2a_history \
    --data $D --kit $K --out ../research/runs_v13/submit_check.json
# 3. per file: format check against the corpus (Track 1 doc key "id", Track 2 "doc_id")
python $K/format_checker.py ../research/runs_v13/submit/test/1a/iota.txt --corpus $D/track1_tempo/iota/documents.jsonl --doc-key id
```

Do not run `submit.py` while another GPU job (vLLM generation) is running: on 2026-11-02 the two together overcommitted
the 8 GB GPU and both stalled. Long GPU jobs: Windows takes 1.7–5.3 GB of the 8 GB GPU; ReasonEmbed saves document vectors every 2,000 documents,
so an interrupted `submit.py` can simply be restarted. The cost estimate for the test set is in RESULTS section U.

## Rules

1. Never modify `RETECO/` or the datasets.
2. Never report a number that did not come out of a run; log every run in `research/LOG.md`.
3. Fit, tune and select on **train**. Dev is scored once with the frozen configuration.
   (Earlier weeks looked at dev results for fixed conditions; see LOG for what was seen when.)
4. Examples are sampled with a fixed seed (20260921) by a rule written before reading them.
   Never resample. Labels proposed by the assistant are preliminary until a human confirms them.
5. Negative and surprising results are reported as results.
6. Do not read document ids for ranking (Track-2 ids reveal gold documents — see LOG 2026-10-13), not even
   to break ties (sha1 key), and never show ids to the LLM. Track-2 corpus file order also reveals gold.

## Gotchas

- Track-2 qids are `<conv>_turn_<n>`; the curated sample uses `<conv>#turn<n>`. A mismatch scores silently as 0.
- The corpus is never split: always retrieve over the full domain corpus, for train and dev.
- Exact score ties are common in the BRIGHT-derived Track-2 corpora (duplicate passages). Always break
  ties deterministically with `tiebreak.key` (sha1 of the id); bm25s's own order depends on the requested depth.
- Track-2 qids (`2_turn_1`, …) repeat across the BRIGHT domains: key anything per (domain, split, qid).
- In BRIGHT-derived Track-2 corpora long documents are mostly gold (biology 71%); passage-max scoring benefits.
- Score dense retrieval in float32: fp16 matmul flips near-ties (recall@10 0.98 against exact).
- Encoders truncate on the right: put the current question before the history.
- Large jobs one at a time (12 GB RAM): an indexer next to an ANN build was OOM-killed once.
- `snowflake-arctic-embed-m-v2.0` and `nomic-embed-text-v1.5` remote code does not run under transformers 5.x.
- Do not run the organisers' `build_release.py` / `download_raw.py`.
