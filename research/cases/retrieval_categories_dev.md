# Who finds the gold documents? BM25 vs dense retrieval, dev (week 4)

Generated by `scripts/case_study.py` from `research/runs_v12/categories/categories.json`
(`scripts/gold_categories.py`). Tables are computed, not typed. Readings and error labels
are hand-written by the assistant and are **preliminary**: no human has validated them.

**What this is.** For every gold document of every dev topic we ask: is it in the BM25
top k, in the dense top k, in both, or in neither? This answers the meeting question
"what does BM25 retrieve, what does the embedding retrieve, and what does neither find" —
with counts over all domains, and with real examples.

**Systems** (both over the full domain corpus, depth 1000, ties broken by doc id):

- **BM25**: bm25s, Lucene BM25 (k1=0.9, b=0.4), Snowball stemmer + English stopwords —
  reproduces the official baseline (Track 1 macro 1a 0.1127 vs official 0.1147).
- **Dense**: `BAAI/bge-small-en-v1.5` (33M parameters, revision `5c38ec7c`), query
  instruction from the model card, 512-token window (longer text is cut off), exact
  cosine search over the whole corpus on the GPU.

**Conditions**: Track 1 `1a` (whole query) and `1b_query+step`; Track 2 `2a_current`
(current turn only) and `2a_history` (history + turn; the dense side uses the
current-question-first string chosen on train).

**Unit and depths**: one (topic, gold document) pair; k = 10 (what nDCG@10 sees) and
k = 100 (a typical candidate pool for a reranker).

**Integrity**: this is diagnosis on dev. Nothing here was used to choose a model, a
parameter or a fusion weight; those were fixed on train before this analysis was run.

**How the examples were chosen** (rule written into the code before any example was
read): conditions 1a and 2a_current; category at k=100; all pairs sorted, shuffled with
`random.Random(20260921)`; the first two pairs per track whose query has not been used
yet. No example was replaced after reading. A larger sample drawn with the same rule is
labelled in section 4.

## 6. Data notes found during this analysis (not used by any system)

- **Track-2 document ids encode the construction.** In the five StackExchange-derived
  domains, 100% of gold documents (train+dev) are named `<question>_doc_<n>`, while only
  1.1–1.5% of corpus documents have that form; 64–76% of `_doc_` documents are gold. Most
  negatives are `<question>_google_neg_<n>`. A system reading ids could exploit this; ours
  never read ids. Worth reporting to the organisers in case the hidden test set is built
  the same way. (`scripts/id_artifact.py`, `research/runs_v12/id_artifact.json`.)
- **Exact duplicates in Track 2.** BRIGHT-derived domains contain 5–42% documents that
  belong to an exact-duplicate group (robotics 42%); StackExchange domains none. See the
  indexing-order study in `research/RESULTS.md`.
