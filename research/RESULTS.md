# Results

Generated by `scripts/make_results.py` from the run files; every number comes from a logged run (`research/LOG.md`). Split is **dev** unless stated. Metric: binary nDCG@10, macro-averaged over domains.

Data: **Track 1 = release v1.1** (deduplicated, 1,167,159 docs); Track 2 unchanged. Week-1 Track-1 numbers were on v1.0 and are not comparable; they are kept in git history.

Systems:

| tag | what |
| --- | --- |
| `kit-python` | week-1 pure-Python BM25, starter-kit tokeniser (lowercase regex) |
| `bm25s-plain` | bm25s, Lucene BM25 formula, same plain tokeniser |
| `bm25s-lucene` | bm25s + Snowball English stemmer + English stopwords |
| `+bge rerank` | `BAAI/bge-small-en-v1.5` (33M, CPU) reranking the BM25 top-100 |
| `cap@100` | oracle over the BM25 top-100: the ceiling any reranker can reach |
| `official` | organisers' pyserini baseline (BASELINE_RESULTS.md) |

## 1. Reproduction of the official BM25 baseline

| sub-track | kit-python (v1.0 data) | bm25s-plain | bm25s-lucene | official |
| --- | ---: | ---: | ---: | ---: |
| Track 1a | 0.0754 (9 dom.) | 0.1224 | 0.1127 | 0.1147 |
| Track 1b Query+Step | 0.0744 (9 dom.) | 0.1248 | 0.1181 | 0.1177 |
| Track 2a current | 0.1445 | 0.1490 | 0.1759 | 0.1827 |
| Track 2a +history | 0.3661 | 0.3748 | 0.4034 | 0.4379 |

Two different explanations, one per track. **Track 2** (same data in both weeks): the analyzer carries the gap — 0.1445 (starter-kit tokeniser) -> 0.1490 (Lucene BM25 formula, same tokens) -> 0.1759 (Snowball stemming + stopwords) against 0.1827 official. **Track 1**: the week-1 gap was already small on the same 9 domains and v1.0 data (0.0754 ours vs 0.0835 official); the jump to ~0.11 is the v1.1 deduplication, not the analyzer — on Track 1 the unstemmed run is in fact slightly above the official figure, so stemming is not uniformly better.

Macro agreement is now within 0.002 on Track 1 and ~0.007 / 0.035 on Track 2 (current / +history).

Per-domain agreement is weaker than the macro agreement (differences up to 0.04, e.g. history 0.0615 vs 0.0873), so per-domain claims still need the official pipeline.

## 6. E2 — explicit-date reranking (train): negative

Fixed rules over the BM25 top-100, no tuning: promote documents whose stated years fall inside the query's year span ±1 — across the whole list (`hard`), inside the top 20 or top 10, or fused with the BM25 order by RRF.

| variant | macro nDCG@10 | Δ vs BM25 |
| --- | ---: | ---: |
| BM25 (no reranking) | 0.1005 | — |
| hard | 0.0909 | -0.0096 |
| top20 | 0.0945 | -0.0060 |
| top10 | 0.0971 | -0.0034 |
| rrf | 0.0946 | -0.0059 |

Every variant loses, in every domain. Last week's feasibility check compared gold passages with *random* corpus documents (41% vs 11% year overlap); among BM25's topically similar top-100 the year signal no longer separates gold from non-gold. A date-aware system would have to use the signal inside the ranking function or in a recall stage, not as a post-hoc reorder.
