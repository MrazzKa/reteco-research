# Paper tables (SemEval system paper)

Generated by `scripts/paper_tables.py`; nothing here is typed by hand. Re-run after any of the inputs changes:

```bash
cd ~/semeval-reteco/reteco-research/scripts
~/semeval-reteco/.venv/bin/python paper_tables.py --root .. --data ../../reteco_data_v11 --kit ../../RETECO/starter_kit [--digits 3]
```

Each `.tex` is a `table`/`table*` with booktabs, caption and label (`\usepackage{booktabs}`). `numbers.json` holds every
number the text may cite (4 decimals; `<key>.ci_lo` / `<key>.ci_hi` for 95% intervals). Placeholders (a single
comment line) are written when an input does not exist yet; the script prints a WARNING/NOTE for each fallback.

## Notes on individual tables

- **Table 1.** Train = rule-8 subsample (≤ 30 topics per domain, the numbers the runs were chosen on); the official
  BM25 train numbers are on the full train split and are kept only in `numbers.json` (`bm25_official.*.train_full`).
  Pool-100 variants (`1a_p100`, `2a_nomaxp_p100`) are excluded (supervisor decision 2026-11-11).
- **Table 4.** "--" in a train column means no bootstrap was run for that comparison in the original experiment:
  either the candidate was not the train winner (rule 7 MaxP on Track 1, rule 9 temporal, rule 13 for 1a / 2a) or
  the cross-encoder grid (section Q) reported macros only. The plain difference is shown; nothing new is computed.
  MaxP for 2a current is the rule-10 comparison after ReasonEmbed (A = MaxP pool, B = no MaxP), not the hybrid-stage
  rule-7 result (+0.014 on train, adopted there and later removed by rule 10). Pool 100: adopted on train for 1a
  and 2a current (rule 17), dropped by the supervisor for cost (not a train rule).
- **Table 5, test-time estimate without pool 100** (keys `compute.no_p100.*`, arithmetic in `_compute_arithmetic`).
  The C1 cold dress rehearsal (dev size) ran `1a_p100` first, so it paid the ReasonEmbed cost for the pool-100
  documents (41,431 docs, 6,030 s) and the pool-50 `1a` run then found them cached; the same holds for
  `2a_nomaxp_p100` before `2a_nomaxp` / `2a_maxp`, and `1b` found its documents encoded by the paused first attempt.
  Without pool 100 the estimate is: C1 wall time of every non-p100 run (BM25 indexing kept fixed, the rest scaled by
  test/dev topics as in `c1_report.py`) **plus** the ReasonEmbed time of the documents those runs would have to encode
  themselves, counted as unique (domain, doc) pairs in the research dev pools (`foreign/runs/*__none.tsv`):
  1a = all 1a pool-50 docs (22,720), 1b = 1b pool-50 docs not in the 1a pool (8,750), 2a = docs of the 2a current
  pools (no MaxP, MaxP) not in the 2a history pools (8,625 after removing the 289 the C1 MaxP run already paid);
  rates from C1 (Track 1 6.87 docs/s, Track 2 7.61 docs/s). Check of the counting: the 2a history pool-50 count
  (16,721) matches the 16,642 documents the cold run encoded for `2a_history`. LLM pre-generation scaled by inputs.
  Result ≈ 1.6 h for the full test (1a 44 min, 1b 23 min, 2a 19 min, pre-generation 11 min) vs 2.1 h with pool 100.
  The old 2.1 h figure under-counted 1b (its documents were encoded in the paused run).
- **Table 7.** "Cached" = the reported dev numbers (LLM texts generated in larger batches); "fresh" = the C1 run
  from empty caches. Only the hybrid without ReasonEmbed (`1a_noRE`) moves by more than 0.005.
